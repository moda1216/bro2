1 · 下一步①：读数修正（measurement-wiring，不是能力优化）

失真机理

历史测量脚本的 configOverride 只覆盖 maxSteps=12，maxTokens 靠 agentos.config.json 默认值 60000 累计静默熔断生效。而每步上下文重建会把历史 token 重复计费——v2.31.0 实测 16 次 token 中位数 56540、最大 75138，5/16 在 4~6 步就撞 guard(tokens)，12 步预算形同虚设。报告的 budget 字段却只写了 maxModelCalls，完全没披露真正的 binding constraint。

修正 ≠ 刷分。 上一版明确拒绝「调大 maxTokens 抬高数字」。本轮把 maxTokens 提到成套值 120000（= 12 步 × 10000 token/步，依据 v2.31.0 实测约 10280 token/步），是让「名义 12 步预算」真正可用——这是修尺子，不是加资源换成绩。因此报告把两种口径并列呈现，并锁死归因。

诚实二次判读：判据机械全绿 ≠ 机制有效

预注册判据结果原样保留（不事后改判据）：P1∧P2∧P3 机械成立。但按项目防 reward-hacking 纪律（src/rsi/contrast.ts「自报分数提升但无行为/效应支撑 → 拒绝」），必须检查效应量能否被噪声解释：

holdout / 反证锚点不退化 / 全 fail无泄漏、无退化，但也无独立正证据
机制结论：证据不足（噪声主导）：判据机械全绿，但不构成机制有效证据
判据 P1∧P2∧P3 机械全绿，但 A−C 通过差仅 1 个 trial、可被 C 组独有的 1 次 provider_error 端点噪声完全解释；且软预警在 A 组 12 次运行里仅触发 1 次，机制几乎未被检验。据此判定「证据不足（噪声主导）」，不构成机制有效的可靠证据：维持默认关闭、不据此开启、不改 L4/verdict。
软预警仍默认关闭，不因本轮改变行为。预注册判据结果原样保留（不事后改判据），本段为只增的二次判读层；反证锚点 assign-seats 三组全 fail，确认无答案泄漏。

3 · 诚实边界（红线，全程未破）

  • 小样本（4 任务、每组 K=3、共 36 次）、免费匿名端点（kilo 路由模型不固定）、单次随机性大
  • 读数修正前后通过率差归因于『测量预算接线成套化』，不是 bro2 能力变化；不写 external-results.json、不改 L4/verdict
  • 校准口径提高了 maxTokens 上限（60000→120000），这是修尺子不是加资源刷分；差异不得包装成能力优化
  • 机制复验为同集前后对照，属弱证据；软预警仍默认关闭，不因本轮改变默认行为
  • bro2 自跑、非第三方复核；公开 verifier 为上游 pytest，healthy 已双向验证
  • verifier 健全性：4/4 SOUND（沿用 v2.30.0 双向验证：空工作区 fail / 官方 oracle 解 pass）（空工作区必 fail / 官方 oracle 解必 pass，模型无关）。
  • 全程自跑、非第三方复核；本轮是读数校准与机制复验，不是「能力水位提升」——leadership.verdict = not-proven、L4 = not-achieved 均未改。
