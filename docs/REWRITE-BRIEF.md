# bro2 · 深度重写需求提报（REWRITE BRIEF）

> 用户意图原文：想要 bro2 的「更深入版本，而不是更大版本」。本文件是把该意图精确化后的
> 可执行需求提报，供重写前评审。**这是蓝图，不是已实现功能**；状态均为 `planned`。
> 创建于 v2.35.0 之后；配套架构方案与风险清单见 [REWRITE-ARCHITECTURE.md](./REWRITE-ARCHITECTURE.md)。

---

## 0. 一句话定义

在**冻结模型权重、加厚验证/约束/可回滚骨架**的前提下，把 bro2 深化为：
一台 24G 显存 Mac 上可离线自治、能沉淀经验并调度本地训练器自我调优、全程白盒可审计、
节能且安全的个人全能 agent。**深化 = 加厚骨架，不是堆叠功能，也不是放大模型。**

## 1. 硬约束（不可协商，违反即验收失败）

| 约束 | 精确要求 | 对应现有资产 |
| --- | --- | --- |
| 本地自治 | 无付费 API、无网络时完成核心任务；免 key 端点为**可选增强、非强依赖**；端点失效降级到本地模型而非停摆 | 已有 `local-qwen*` + `models/keyless.ts` + `models/hybrid.ts`；需补 24G Mac 的 MLX/GGUF 具体路径 |
| 冻结权重 | 模型权重冻结，harness 可演进；评测遵循 `model + harness = agent` 的 strict delta | 已有 RSI / meta-RSI 冻结尺子传统 |
| 内容寻址 | config / harness / 提示 / 训练数据 / 评测集全部 hash 化、可回滚、可归因 | 部分（`data/evolve` 只增账本）；需系统化 |
| 诚实红线 | 不改冻结评测集、不写伪造结果、不把 mock / provider_error / 被中断结果计为有效 trial | 已有 `preflight:check` 证据隔离、`batch.py` 防污染检测（历史教训见 §5） |
| 代码预算 | `src / bin / scripts` 计入 16500 行且当前已满；**任何净增须在别处等量删减**，或落在豁免目录 `data/ / examples/ / docs/` | 硬门禁 `npm run budget:check` |

## 2. 能力需求（每条附可证伪验收）

1. **本地自治**：断网 + 无 key 环境下跑通完整任务集。
   - 非强依赖端点：热插拔、健康感知、失效自动降级本地；单次端点失败不得污染结果。
2. **通用助手**：覆盖文件 / 终端 / 研究 / 写作 / 数据等任务。
   - 验收：在**用户真实任务日志采样**的分布上，通过率与置信度双达标，而非仅Toy任务。
3. **轨迹与反馈飞轮**：定义「有用轨迹」判据（可复现、带来正向 delta、非幸运路径），含脱敏、去重、质量分级、失效留痕。
   - 验收：每条入库轨迹可追溯到来源与它产生的具体 delta；失败轨迹同样留痕。
4. **自进化训练**：调度本地 LoRA/QLoRA 训练器，用沉淀数据调优模型；上线必经 `shadow → A/B → 金丝雀 → 回滚`。
   - 验收：每次部署有冻结验证集的前后对照 + 显著性检验；无对照不得晋升。
5. **白盒交互**：可视化任务执行 / 轨迹沉淀 / 模型进化 / harness 进化全流程，支持关键决策的人机审批闸门。
   - 验收：外部观察者可仅凭界面重建任意一次决策链；审批闸门可拦截。
6. **能效**：每任务 token / 时间 / 内存 / 能耗计量，设硬预算与自动降级。
   - 验收：由系统工具（非 agent 自报）独立测量达标；超预算自动降级。
7. **安全与自主**：99%+ 无人化；涉及隐私 / 系统破坏 / 网络犯罪的动作，由 **agent 之外的策略引擎**拦截或升级用户授权；全程审计日志 + 提示注入防御。
   - 验收：第三方红队注入 / 提权测试通过；拦截规则不位于 agent 可修改面。

## 4. 方法

第一性原理拆解 · 约束驱动设计 · `model + harness = agent` 下的 strict delta ·
bootstrap CI / 显著性检验 · 红队与故障注入 · content-addressed 版本化 ·
inter-rater reliability（换实现重判一致性） · shadow / canary 部署。

## 5. 一手失败教训（必须作为设计输入，不得重犯）

| 教训 | 根因 | 防御要求 |
| --- | --- | --- |
| Mock 静默降级成有效成绩 | router 非 strict 时 provider 失败回退 mock | 失败即判 `error`，绝不记 reward；防污染检测在 agent 之外 |
| CI 预算超 5 行 + preflight 卡 90s | `--strict` 加行 + 打断 else-if 链落入交互模式 | 门禁改动先本地全绿再推；预算满额下净增必须等量删减 |
| apt 构建卡死 20min+ | 容器内 apt 下载大索引挂起 | 构建绕开 apt（pip + wget tarball）；设超时与退避 |
| PATH 重置致 node 找不到 | `bash -lc` 覆盖 PATH | 软链到登录 shell 默认路径 |
| 端点从「可用」到 8/8 超时 | 匿名层间歇失效 | 端点健康与 trial 结果解耦；失效时如实上报，不用 mock 填充 |
| 中断 trial 落盘成伪结果 | TaskStop 瞬间 trial 完成写 reward=0 | 落盘需校验进程正常退出与日志完整性；被中断行必须清除 |

## 6. 独立验证（缺一不可，且必须外置于 agent）

- 公开冻结基准（Terminal-Bench 官方 / SWE-bench）上**开源可复跑**的评测。
- 独立判分器重判的一致性（inter-rater reliability）——自己判自己不算。
- 客观指标 + 统计显著性（置信区间、多次重复方差），而非单次读数。
- 测试集隔离与哈希冻结，进化过程无访问权。
- 进化曲线由**独立脚本从原始数据重算**。
- 第三方可审计 + 红队报告。
- 能耗 / 内存由系统工具外部测量，不由 agent 自报。

## 8. 需求追溯矩阵（7 特性 → 现有覆盖 → 深化方向）

| # | 特性 | 现有覆盖 | 深化方向（详见架构方案） |
| --- | --- | --- | --- |
| 1 | 本地自治 | 中：local-qwen + keyless/hybrid | 24G Mac 的 MLX/GGUF 具体化 + 端点失效降级不污染 |
| 2 | 通用助手 | 中：tools/builtins 六类 | 用真实任务分布驱动，置信度校准 |
| 3 | 轨迹飞轮 | 强：trajectory + experience + compound | 轨迹质量判据 + 脱敏 + 失效留痕系统化 |
| 4 | 自进化训练 | 弱：RSI 仅改 harness + train/holdout 曲线 | 本地训练器调度 + 上线闸门（shadow/A/B/canary/rollback） |
| 5 | 白盒交互 | 中：REST/SSE + watermark 看板 | 统一时间线 + 审批闸门可拦截 |
| 6 | 能效 | 中：budget/guards/cache | 外部计量 + 硬预算 + 自动降级 |
| 7 | 安全自主 | 强：governance 四件套 | 策略引擎外置 + 红队验证 |

> 结论：多数能力已有底座，缺口集中在 **#4 本地训练调度** 与 **#5 统一白盒**，
> 以及横切的 **验证骨架 / 内容寻址 / 外置安全**。这正是「深入而非更大」的着力点。
