# MAF · MetaAgent Foundry 产品设计

状态：v0.1 设计基线（2026-11-27）  
归属：bro2 的 Agent 生成、进化、编排与白盒产品层  
诚实边界：本文描述目标架构与验收契约，不代表功能已经实现；能力结论仍以可执行证据为准。

## 1. 产品定义

**MAF = Agent 生成与进化引擎 + 自动化编排平台 + 白盒观测与治理中心。**

母 Agent 根据场景，从 Block 库组合出带拓扑、工具和提示的垂直 Agent；每次改进必须可判分、可追溯、可回滚。平台负责长期运行和人工治理，白盒中心负责解释行为、演变与能力成长。

三部分缺一不可：进化引擎决定 Agent 是否可信，平台决定是否可用，白盒决定是否可理解、可监督、可问责。

## 2. 目标与非目标

### 2.1 目标

1. 将场景变量、可执行判分方式和预算上限编译为垂直 Agent 候选。
2. 用 Block、Agent 基因组和有向拓扑表达候选，而不是只创建一个 Prompt Preset。
3. 对候选执行单元测试、隐藏集、历史回放和影子双跑，并与基线配对比较。
4. 只有满足统计、回归、安全和成本门禁的候选才可发布；所有版本永久归档。
5. 支持持久化任务 DAG、并发、重试、取消、恢复、幂等、灰度和撤权。
6. 将专家 Agent 的经验证能力蒸馏为共享 Block/Skill，经专项和全局双门禁后吸收。
7. 在一个白盒入口中完成任务发起、监控、证据展开、审批、发布、复现、回滚和撤权。

### 2.2 非目标

- 不修改模型权重，不宣称训练了基础模型。
- 不允许 Agent 修改目标契约、评分器、隐藏测试、预算上限、晋升门或审计日志。
- 不用 LLM-as-judge 决定通过，不允许生成器与评估器同源，不以单次运行下结论。
- 不做无界 RSI，不把机制跑通写成能力已提升，不把 mock/error/prepare-fail 计为成功。
- 不以 Agent、Block 或事件数量增加冒充能力成长。

## 3. 冻结层与可进化层

| 层 | 内容 | 修改者 |
|---|---|---|
| 冻结层 | 目标契约、fitness/verifier、隐藏测试、预算上限、权限上限、晋升门、审计日志 | 仅人类，通过独立变更流程 |
| 可进化层 | Block 实现、Agent 基因组、拓扑、工具白名单内配置、提示、技能记忆 | 母 Agent，经白名单变异与门禁 |
| 运行治理层 | 暂停、取消、审批、灰度比例、撤权、回滚 | 人类或满足冻结条件的自动化策略 |

候选只能引用冻结的 `verifierId/version`，不能携带或替换评分实现。权限采用交集：候选权限不得超过父代和场景授权上限。

## 4. 核心对象与数据契约

### 4.1 场景 Scenario

```text
scenarioId / version / name / domain
inputSchema / outputSchema / constraints
visibleCasesRef / hiddenCasesRef / replayCasesRef / shadowCasesRef
verifierId / verifierVersion / verifierHash
budgetPolicyRef / permissionCeilingRef
createdBy / createdAt / contractHash
```

场景未提供变量、判分方式或预算时，状态只能是 `incomplete`，不得启动生成。

### 4.2 Block 与能力包

```text
blockId / version / kind / implementationHash
inputSchema / outputSchema / declaredDomain / measuredDomain
testsRef / evidenceRefs / parentVersion / diff
status: draft | shadow | active | deprecated | rejected
selectionWeight / createdAt / archivedAt
```

Block 的适用域只能来自实测。低分版本不删除，仅降低作为父代或路由候选的概率。共享 Skill 使用相同证据和版本原则。

### 4.3 Agent 基因组与谱系

```text
agentId / version / parentVersion / scenarioId
blocks: [{ blockId, version, config }]
topology: [{ from, to, condition? }]
prompt / toolRefs / skillMemoryRefs
modelPolicyRef（冻结引用）/ permissionRefs（不扩权）
genomeHash / snapshotHash / proposalReason
status: draft | evaluating | shadow | active | rejected | retired | revoked
```

`genomeHash` 标识可进化结构；`snapshotHash` 覆盖代码、Block、拓扑、技能记忆、数据和工具配置，作为完整回滚单位。

### 4.4 任务与运行身份

```text
scenarioId / taskId / runId / rootRunId / parentRunId
agentId / agentVersion / genomeHash / snapshotHash
causationId / correlationId / idempotencyKey
modelId / verifierId / verifierVersion / evidenceRefs
```

`Task` 是长期定义，`TaskRun` 是一次执行，`TaskAgent` 是可复用资产，三者不得混用。子 Agent 必须持久化父子关系，子任务返回文本不等于执行成功。

## 5. 生成与进化循环

```text
场景输入
  → 完整性检查
  → 信号与失效模块定位
  → 白名单变异提议（必须填写理由）
  → 内容寻址候选与不可变快照
  → 沙箱执行四类评测
  → 配对统计与回归门禁
  → 拒绝归档 / 影子运行 / 人工审批
  → 灰度与原子发布
  → 持续监控
  → 保持 / 降权 / 撤权 / 回滚
```

变异白名单包括：增删或替换 Block、调整拓扑边、修改 Block 配置、修改提示、更新技能记忆。禁止修改冻结文件、扩大工具权限、隐藏失败、改变统计口径或删除不利样本。

## 6. 可执行评测与统计门禁

### 6.1 四类证据

| 证据 | 用途 | 硬要求 |
|---|---|---|
| 单元测试 | 验证可见功能契约 | 记录输入、退出码、输出摘要和耗时 |
| 隐藏 Holdout | 防止过拟合可见用例 | 候选生成过程不可读取隐藏内容 |
| 历史回放 | 验证既有真实/固定轨迹上的行为 | 明确标注 REPLAY，不冒充新实时执行 |
| 影子双跑 | 基线与候选在相同输入下并行对照 | 候选无真实写权限，副作用被隔离 |

只有执行完成且 Verifier 可判定的样本参与分数。超时、provider error、mock、prepare-fail、基础设施失败均保留证据但不计成功。

### 6.2 晋升规则

1. 候选与基线使用相同任务、模型、权限上限和资源预算。
2. 采用逐任务配对比较，报告有效样本量、差值、置信区间和效应量。
3. 默认最小效应量为 `0.05`；95% 配对 bootstrap 置信区间下界必须大于 0。
4. 有效配对样本不足 64 时必须标记 `power=insufficient`，只能进入影子或人工复核，不得自动宣称显著提升。
5. 可见集、隐藏集、回放和影子集均不得出现新增失败；全局回归不劣化。
6. 权限违规、跨域误用、冻结层修改、审计断链任一出现即拒绝。
7. 单位成本不得高于冻结预算；成本下降不能抵消正确性退化。

小样本闭环可以验证机制和失败拒绝，但不得写成统计显著或能力已证明。

## 7. 发布、灰度、回滚与失效

- 发布前保存不可变完整快照，并以原子指针切换当前版本。
- 默认灰度阶段为 10% 影子、10% 受控真实流量、50%、100%；v0.1 无真实流量时只验证状态机和影子阶段。
- 回滚必须恢复代码、Block、拓扑、提示、技能记忆、数据和工具配置，而不是只改一个版本号。
- 回滚生成新的审计事件，不重写或删除旧历史。
- 监控发现正确性退化、跨域误用、权限违规或成本超限时可自动暂停；恢复需要满足冻结条件。
- 撤权立即阻止新运行，并尽力取消在途运行；已产生的证据继续保留。

## 8. 自动化编排平台

### 8.1 任务 DAG

节点包含 Agent 版本、输入映射、依赖、幂等键、重试策略、超时和验证器；边表示数据或控制依赖。禁止循环依赖，动态新增节点也必须通过校验。

### 8.2 持久化与恢复

任务、节点、租约、尝试、发布指针和审计事件落盘。执行器通过租约取得节点，完成时以幂等键提交结果。进程重启后：

1. 过期租约恢复为可领取状态；
2. 已提交幂等结果不得重复执行副作用；
3. 未完成依赖继续等待；
4. 失败节点按冻结策略重试或进入死信；
5. 恢复过程本身写入审计事件。

### 8.3 触发与治理

支持手动、API、定时和事件触发；统一进入同一持久队列，不建立旁路执行。提供暂停、恢复、取消、重试、灰度、撤权和死信处理。

## 9. 能力分裂、路由与全局吸收

### 9.1 分裂

当用户显式请求或某类任务信号达到阈值时，从通用基座继承冻结治理约束，生成专项候选。候选必须在目标域优于通用基线，才可成为 Active TaskAgent。

### 9.2 路由

路由器只依据实测适用域、任务签名、历史有效证据、成本和当前状态选择 Agent。域不匹配时拒绝自动路由，而非“尝试一下”。专家处于 shadow/rejected/revoked 时不得承接真实任务。

### 9.3 全局吸收

从多条专家成功和失败轨迹中蒸馏共享 Block、Skill、验证清单或恢复策略。候选需重新通过：

```text
专项增益 + 未见同类任务迁移 + 全局 Holdout 不劣化 + 权限/协议/成本约束
```

全局能力提升包括“自身更会做”和“更会选择专家”；高度垂直的能力优先留在专家内，避免无限膨胀主 Prompt。

## 10. 白盒产品中心

### 10.1 P0 最小操作台

- 场景提交与完整性校验；
- 候选、Block、拓扑、父代、Diff 和理由查看；
- 四类评测原始证据、有效样本和统计区间展示；
- 审批、拒绝、发布和回滚；
- 实时事件、历史回放和 REPLAY 明确分源；
- 操作审计与证据导出。

### 10.2 P1 编排与谱系

- 全局任务 DAG、节点状态、租约、重试、取消和恢复；
- Agent Registry、版本树、路由命中、灰度和撤权；
- 服务端全量历史分页与过滤，不依赖固定会话数或事件数截断。

### 10.3 P2 成长中心

- Agent 演化树、Block/Skill 版本 Diff；
- 专项能力、OOD 迁移、全局回归、复用率和单位成本曲线；
- 晋升、拒绝、降权、失效和回滚原因；
- 一键复现实验，展示模型、代码、配置、数据和 Verifier 版本。

UI 只是事实存储的投影，不维护另一套可篡改的“成长结论”。

## 11. API 与存储边界

建议统一挂载 `/api/maf`：

```text
POST /scenarios                 创建/校验场景
POST /candidates                生成候选
POST /candidates/:id/evaluate   执行四类评测
POST /candidates/:id/promote    统计与治理门禁
POST /agents/:id/publish        灰度/原子发布
POST /agents/:id/rollback       完整快照回滚
POST /agents/:id/revoke         撤权
POST /tasks                     创建持久 DAG
POST /tasks/:id/cancel          取消
GET  /tasks /runs /agents /blocks /capabilities /audit
GET  /events?cursor=...         有界分页，游标稳定
GET  /reproduce/:runId          返回完整复现清单
```

存储采用只增 JSONL 审计日志 + 内容寻址快照 + 可重建的当前状态索引。当前状态损坏时可由日志重建；业务档案不得因 UI 清理或低分而删除。

## 12. 默认资源预算

首个可执行编程场景采用保守档：

```text
单候选评测上限：10 分钟
候选评测并发：2
单任务修复尝试：3 次
单节点超时、重试和输出大小：由场景冻结策略进一步收紧
```

所有超限均产生明确证据并终止或拒绝，不得静默扩容。v0.1 默认使用确定性本地 fixture 验证机制；外部模型不是闭环成立的必要条件。

## 13. 分阶段交付与验收

### P0 · 进化闭环与平台骨架

交付场景、Block、基因组、不可变谱系、候选生成、四类评测、统计门禁、发布/回滚和最小操作台。

验收：一个候选被正确晋升、一个退化候选被拒绝、一个越权候选被拒绝；回滚后所有配置哈希与上一已验证版本一致；UI 可完成发起、查看证据、审批、发布和回滚。

### P1 · 持久化编排与生命周期

交付 DAG、队列、租约、重试、恢复、取消、幂等、路由、灰度、撤权和历史分页。

验收：执行中强杀进程后可恢复；同一幂等键无重复副作用；依赖顺序正确；取消和撤权生效；父子因果树可从持久事件独立重建。

### P2 · 能力吸收与成长中心

交付共享能力蒸馏、专项/全局双门禁、能力失效、演化树、成长曲线和复现清单。

验收：至少一个共享能力从专家轨迹产生并通过未见任务与全局回归；另一个无迁移证据的候选被拒绝；任何成长数字均可追溯到原始证据。

## 14. 总体验收指标

- 错误接受率相对基线下降，且已知越权/退化 fixture 的错误接受为 0；
- 可回滚发布比例 100%，回滚后配置与目标快照一致；
- 自动路由跨域误用为 0；
- 固定场景、模型、数据、配置和 Verifier 下复现成功率上升；
- 单位有效任务成本不高于冻结预算；
- 所有晋升、拒绝、失效和回滚均有完整证据链；
- 样本不足时结论恒为功效不足，不产生显著性或通用能力声明。

## 15. 实施纪律

1. 先修身份、证据和持久化，再增强生成智能，避免在不可信地基上扩自治。
2. 平台和白盒是正式验收项，只降低实现优先级，不删除产品目标。
3. 不为通过门禁而放宽判分、删除失败样本或隐藏限制。
4. 代码预算、零运行时依赖和现有发布门禁继续有效；通过重构和删除冗余腾挪空间，不把生产逻辑藏入示例目录。
5. 每阶段保留真实测试、故障注入、浏览器验证和远程同步证据；未完成项明确标注，不以设计文档冒充实现。
