一、根因（比端点问题更深）

bin/agentos.ts run --task 走 runCLI，原先不调用 os.router.setStrict(true)。而 router.order() 在非 strict 下返回 [current, ...所有其他 provider]——任一 provider 失败就静默降级到 mock，产出「本次由离线 Mock 模型驱动」的假终答。

为什么 eval 没事src/observability/eval.ts:426,430 的 eval 模式显式 setStrict(true)；但外部 Terminal-Bench 评测走 batch.py 的 run --task，此前不受 strict 保护。
真实影响ovh/llm7 一旦 429/失败 → bro2 降级 mock → batch.py 防污染判为 mock-fallback / provider_error → 有效 trial 无法产出。此前误判为纯端点问题，实为「harness 评测模式未开 strict」叠加「端点配额耗尽」。
诚实边界防污染红线（mock/provider_error 不计 reward）全程正确工作，未误计分。bug 在于评测缺 strict 保护导致进度停滞，不是虚报成绩。
